# Промт: Telegram-бот для мониторинга новых объявлений на Avito

## Контекст и цель
Я занимаюсь перепродажей компьютеров и компьютерных комплектующих, которые покупаю
на Avito. Ключевой фактор успеха — скорость: чем раньше я увижу новое объявление
и позвоню продавцу, тем выше шанс купить товар по выгодной цене раньше конкурентов.

Нужен бот, который отслеживает появление новых объявлений в указанных категориях
и городе и присылает ссылки на них в Telegram (личный чат или небольшую закрытую
беседу, публичного доступа нет). Бот только присылает ссылки — расчёт прибыли,
получение телефона продавца и механика «бронирования» объявления не входят
в эту версию.

## Источники данных
Отслеживать нужно объявления по двум направлениям (категориям) на Avito:

1. **Настольные компьютеры**
   https://www.avito.ru/rostov-na-donu/nastolnye_kompyutery
2. **Товары для компьютера → Комплектующие**
   https://www.avito.ru/rostov-na-donu/tovary_dlya_kompyutera/komplektuyuschie-ASgBAgICAUTGB~pm

**Регион:** Ростов-на-Дону. Важно: сортировка/фильтрация должна отдавать приоритет
объявлениям именно в выбранном регионе (а не «по всей России рядом»).

Способ получения данных — **прямой парсинг страниц поиска** (не email/push от
сохранённых поисков Avito — там слишком большая задержка).

## Частота проверки и защита от блокировки
Решение: интервал проверки **~20–30 секунд на каждую категорию**, с случайным
джиттером (не строго фиксированный интервал, а плюс-минус несколько секунд), чтобы
не выглядеть как строго механический бот.

Расчёт нагрузки при таком интервале:
- 2 категории × запрос раз в ~25 сек ≈ **~5 запросов в минуту / ~290 в час** —
  спокойный темп, не похожий на агрессивный скрапинг.
- Худшая задержка до получения ссылки на новое объявление — 20–30 секунд,
  средняя — около 10–15 секунд.

Дополнительные меры защиты от бана (без прокси на первом этапе, но с возможностью
добавить их позже, если понадобится):
- ротация нескольких реалистичных User-Agent и заголовков;
- случайный джиттер интервала запросов (не ровно каждые N секунд);
- обнаружение капчи/403/аномального ответа → автоматическое увеличение паузы
  (например, до 5–15 минут) вместо повторного долбления сайта;
- логирование каждого случая блокировки, чтобы было видно, если частоту нужно
  снизить ещё сильнее.

Важно: для парсинга публичных страниц поиска логин в Avito не требуется — блокировка
привязана к **IP-адресу**, а не к аккаунту. Поэтому несколько аккаунтов Avito сами
по себе не увеличивают скорость; ускорение возможно только через несколько разных
IP (прокси).

### Масштабирование через несколько IP (заложено на будущее, не в MVP)
Архитектурно допустимо в будущем ускорить проверку за счёт нескольких независимых
«воркеров», каждый со своим IP, каждый — в своём безопасном темпе (~20-30 сек), но
со сдвигом по времени друг относительно друга (staggered polling), чтобы суммарная
частота проверки сайта была выше без превышения безопасного темпа для одного IP.
Результаты всех воркеров должны сливаться в единое хранилище дедупликации по ID
объявления, чтобы не было повторных отправок.

**Решение по MVP:** на первом этапе — один воркер, один IP (текущий VPS), без
прокси, интервал 20-30 сек. Архитектуру (хранилище дедупликации, конфигурацию
источников) проектировать так, чтобы позже можно было добавить несколько воркеров
без переделки с нуля, но саму реализацию пула прокси/нескольких воркеров
откладываем до тех пор, пока не станет понятно на практике, что скорости одного
воркера не хватает.

## Основной функционал
1. Периодически (см. раздел выше) проверять обе категории на наличие новых
   объявлений.
2. Присылать в Telegram-чат только **новые** объявления, которых бот ещё не
   показывал (дедупликация по ID объявления, хранится персистентно — переживает
   перезапуск бота).
3. В каждом сообщении присылать:
   - заголовок объявления;
   - цену;
   - район/город;
   - дату и время публикации;
   - прямую ссылку на объявление.
   (Номер телефона продавца получать не нужно — только ссылка.)
4. Поддержка нескольких источников/фильтров одновременно (сейчас два, но список
   должен расширяться конфигом, а не хардкодом).
5. Фильтрация по ключевым словам:
   - включающие (например, только определённые модели/бренды);
   - исключающие (например, «на запчасти», «не рабочий», «сломан», «донор»).
6. Фильтр по диапазону цены (мин/макс), настраиваемый.
7. Бот должен реагировать только на команды из заранее заданного chat_id —
   игнорировать сообщения из любых других чатов.

## Команды бота
- `/start` — приветствие и краткая справка.
- `/status` — состояние бота: работает/на паузе, когда была последняя проверка,
  сколько объявлений отправлено за сегодня.
- `/pause` и `/resume` — приостановить/возобновить мониторинг.
- `/filters` — показать текущие активные фильтры (категории, ключевые слова, цены).
- `/add_keyword <слово>` и `/remove_keyword <слово>` — управление списком
  исключающих ключевых слов на лету, без перезапуска.

## Хранение данных (минимальное)
Задача бота — только присылать новые объявления, а не собирать архив данных.
Поэтому хранить нужно по минимуму:
- ID уже показанных объявлений и время, когда они были впервые увидены;
- **без** полного содержимого объявлений (текст, фото и т.д. не сохраняются).
- Автоматическая очистка старых записей (например, старше 3–7 дней) — новое
  объявление с таким же ID повторно появиться не может, поэтому долго хранить ID
  смысла нет.
- Формат — простая SQLite-база или файл, достаточно лёгкий, чтобы не требовать
  обслуживания.

## Технические требования и деплой
- Использовать имеющийся у меня VPS — отдельный сервер под эту задачу не нужен,
  нагрузка лёгкая (периодические запросы + Telegram-бот, не видео/ML). Минимальные
  требования: 1 vCPU, 1 ГБ RAM с запасом достаточно, даже если парсинг идёт через
  headless-браузер (Playwright/Chromium) — держать один переиспользуемый браузерный
  контекст, не поднимать новый процесс на каждый запрос.
- Бот должен работать круглосуточно с автозапуском при перезагрузке сервера и
  автоматическим перезапуском при падении — через systemd-сервис (или аналог).
- Токен Telegram-бота и другие секреты — через переменные окружения/.env файл,
  не хардкодить в коде.
- Логирование ошибок и уведомление администратора в Telegram при критических
  сбоях (например, если сайт стал недоступен или изменилась структура страницы).
- Технологический стек: вероятно Python + Playwright (headless-браузер, так как
  Avito защищён от простых HTTP-запросов) + python-telegram-bot + APScheduler для
  периодических проверок + SQLite для хранения ID.
- Пошаговая инструкция по разворачиванию на конкретном VPS (установка зависимостей,
  создание systemd unit-файла, настройка .env, проверка логов) будет дана отдельно,
  когда бот будет собран — она зависит от финальной структуры проекта.

## Возможные будущие доработки (не в этой версии)
- Отметка «уже видел» / фильтрация похожих повторных объявлений от того же
  продавца, если это станет проблемой на практике.

## Ограничения и риски (зафиксировано явно)
- Автоматический сбор данных с Avito нарушает пользовательское соглашение сайта —
  есть риск блокировки IP. Принято, что это допустимо, но заложена защита
  (см. раздел «Частота проверки и защита от блокировки»), чтобы не ловить бан
  ежедневно и не требовать создания новых аккаунтов/IP каждый день.
- Структура страниц Avito может меняться без предупреждения — потребуется
  периодическая поддержка/обновление парсера.
